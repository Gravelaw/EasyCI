## Trusted snapshot ingestion

The operator reads a trusted repository; Jenkins does not mount or fetch a
workstation checkout. Snapshots contain only explicit committed candidate/base
history, plus a bundle checksum and Git tree identity. Dirty files stay outside.
Snapshots and their hash parameters are administrator-controlled. Hash identity
does not make arbitrary source safe.

Create an empty local `state/snapshots` directory inside this isolated scaffold.
Initialize **only** a separate copied `examples/demo` repository for the demo,
commit `message.json`, and obtain its full 40-character SHA using `git rev-parse
HEAD`. Do not initialize or alter an existing project repository as part of this
step. Then use the full SHA as both commit and base:

```powershell
python scripts/ci.py ingest --repo "<isolated-demo-repo>" --project demo --commit <full-sha> --base <full-sha> --snapshots "state/snapshots" --snapshot-id demo-v1
```

Retain the printed metadata hash. For the optional Linux agent, copy only this
snapshot into its dedicated named volume through the bounded helper, after
approving these container operations:

```powershell
docker compose --profile tools run -d --name jenkins-local-snapshot-loader snapshot-loader
docker cp "state/snapshots/demo-v1" jenkins-local-snapshot-loader:/snapshots/demo-v1
docker stop jenkins-local-snapshot-loader
docker rm jenkins-local-snapshot-loader
```

The helper has no network, no secret, only the demo snapshot volume, and exits
after five minutes. Never overwrite an existing ID. Record hashes before/after
copy; the agent validates snapshot.json against the submitted hash and then
validates the bundle. Build the demo job with `SNAPSHOT_ID=demo-v1` and the exact
`METADATA_SHA256`. Review result/receipt hashes and approve as `local-admin`.
This demonstrates local artifact delivery only.

For JuliaFlow use project `juliaflow`, snapshot ID `juliaflow-099bb56`, commit
`099bb56f6da8865796f1ab0b2ba8fe5e73d08afa`, baseline
`11856e4d85f6c8ee96446687b4b21057733d9750` (verified locally present), and an
operator-owned snapshot root outside all product checkouts. Put the resulting
snapshot under `C:/JenkinsLocal/snapshots/juliaflow`, preserving its metadata

## Native Windows / WSL enrollment decision

This is a separate approval boundary, not a Compose service. Approve a native
Windows Java 21 inbound node with exactly one executor and label
`juliaflow-windows-wsl`, remote root `C:/JenkinsLocal/agents/juliaflow`. Install a
reviewed copy of this scaffold at `C:/JenkinsLocal/tools` and precreate
`C:/JenkinsLocal/releases/juliaflow` and snapshot storage. Use an approved local
account and a file-based enrollment secret; run agent.jar manually in the
foreground with `-url http://127.0.0.1:8080/ -webSocket -secret @<private-file>
-name <approved-node-name> -workDir C:/JenkinsLocal/agents/juliaflow`. Do not
create a service account, Windows service, scheduled task or new token silently.
Confirm file-secret syntax with that jar's help before enrollment.

The existing runner hardcodes `juliaflow-ci-ubuntu24` and calls WSL as root to
create isolated PostgreSQL jobs and temporary 3 GiB swap. It expects Windows
drive-mounted evidence, Node 25.9.0, Julia 1.12.7 and PostgreSQL 16 inside WSL.
This task's host Node 26.3.0 is not the runner's qualified WSL Node. Calling the
runner is therefore pending explicit approval to use that distro and its
resources, coordination with other jobs, and a working enrolled agent. A separate
WSL distro is the preferable long-term isolation option, but requires a separately
reviewed upstream runner option; this scaffold does not rewrite the runner.
Jenkins' lock cannot serialize commands launched outside Jenkins. Default cold
caches avoid shared warm-cache writes. Warm mode is rejected by this adapter
until a separately qualified project namespace exists.

GitHub synchronization is optional. No GitHub Actions control plane, webhook,
new credential or workflow edit is required. A future secured Git endpoint may
use HTTPS with verified certificates/read-only scoped authentication approved per
action; its repository URL, credential scope and source SHA must be reviewed.
Never enable Jenkins `ALLOW_LOCAL_CHECKOUT` or mount a product checkout instead.
